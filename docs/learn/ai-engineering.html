AI engineering — what it is, where it must not sit

No model in Payment. No chatbot in POST /orders. Two use cases you can try. Terms assume you have never heard “LLM.”

AI engineering is the product around a model: timeout, fallback, cost, tests (evals), and where it must never run. Same idea as Polly and “do not cache order status.” Calling a chatbot from a controller and shipping it is not that.

1. Words from zero

TermMeaningTadka hook
AISoftware that does something that used to need a human guess (language, ranking, images).A label. Too broad to design with.
MLA program fitted on examples, not only if/else.Your order state machine is not ML. It is explicit rules.
ModelThe trained blob you call. This week you almost never train one.Like the fake payment gateway: an external dependency.
LLMLarge language model: predicts likely next text. Fluent ≠ true.Can describe biryani. Can invent ₹1.
PromptInstructions + data you send.A function argument, not a spell.
TokenA chunk of text. Billing and length limits use tokens.Cost and timeout — like a Slow gateway.
HallucinationA fluent wrong answer with no source.“Paneer is ₹50 at Meghana” — check the menu JSON.
EmbeddingNumbers that mean “similar text.”Search “spicy rice” ≈ biryani.
RAGFetch your data, then ask the model (Retrieval-Augmented Generation).GET the menu, put that JSON in the prompt.
ToolThe model asks your code to call an API.Allowed: GET /orders/{id}. Never POST /payments.
EvalA test set: question + expected behaviour.If it invents a dish, the eval fails even if the sentence is pretty.

3. Use case A — Menu Q&A (RAG)

  1. GET /api/v1/restaurants/{id}/menu (Day 6 cache still applies).
  2. Put that JSON in the prompt: “Answer only from this menu. If it is not there, say you don’t know.”
  3. User: “veg under 300 at Meghana?”
  4. If the model names a dish not in the JSON, your eval failed.

Forbidden: changing prices, POST /orders, anything on :5240/payments.

4. Use case B — Status explainer (read-only)

  1. GET /api/v1/orders/{id} only.
  2. Prompt: one sentence from that JSON.
  3. After you killed Payment (Day 8 runbook §2), status Created → “Order was accepted; the charge did not complete because Payment was down.”

Forbidden: POST /payments, POST /orders.

6. What this is not

  • An LLM inside OrdersController or Payment.
  • Shipping without evals or a timeout.
  • Trusting fluent text as a price or a charge.
