Sharded Orders Demo: Runbook

A strict, one-step-at-a-time walkthrough. Every block tells you exactly which terminal window to type it into.

What this is. A guided path through samples/sharded-orders-demo: real Postgres shards, real routing, a real "add a shard, watch it break, then fix it" sequence. If you want the full command reference instead of a guided path, see README.md.

Before you start: Docker Desktop running, this repo cloned, .NET 10 SDK installed. Every command below assumes your terminal's working directory is the repo root (the folder containing samples/).

Windows 11 users: if dotnet run throws FileLoadException ... blocked by an Application Control policy, see the Troubleshooting section at the bottom before continuing.

Terminal legend

T2Watch shard 1
T3Watch shard 2

T5Watch shard 4
T6Stream (feeds live data)

Open T2–T5 once and leave them running for the whole session. You'll watch them fill up across every later step. T1 is where you type everything else.

Step 4 of 6

Act 1: the break (naive hash % N)

If you skipped Step 3, T1–T5 already have 20,000 order_id-sharded rows from Step 0/2. If you did Step 3, you just reseeded the same thing. Either way, continue here.

Step 5 of 6

Act 2: the fix (consistent hashing, grown correctly)

Important: you cannot cheaply convert the naive-hash data from Act 1 onto a consistent-hash ring. That costs almost as much as a full rehash (it's changing two things at once). The cheap-resize property only applies when you're already running consistent hashing. So: reset, and seed fresh, directly under consistent-hash mode.

T1
dotnet run --project samples/sharded-orders-demo -c Release -- reset dotnet run --project samples/sharded-orders-demo -c Release -- seed --count 20000 --shard-key order_id --mode consistent-vnodes --vnodes 150
You should see (real captured)
Routing with: consistent-hash + 150 vnodes/shard (4 shards)
  shard 1:   5,114   25.6%
  shard 2:   4,663   23.3%
  shard 3:   5,160   25.8%
  shard 4:   5,063   25.3%

T2–T5 will show the reset (truncated) then refill with this new baseline on their next poll.

T1
dotnet run --project samples/sharded-orders-demo -c Release -- add-shard --id 5
You should see
Shard 5 reachable. Schema created. Cluster is now 5 shards.
Routing mode is consistent-hash+vnodes - existing rows are NOT yet reassigned.
Run `reshard plan` / `reshard apply` to migrate this shard's fair share in.
T1
dotnet run --project samples/sharded-orders-demo -c Release -- reshard plan --to consistent-vnodes --vnodes 150
You should see (real captured, 17.3%, not the ~80% from Act 1)
Rows to migrate: 3,453 of 20,000 (17.3%, roughly one shard's share of the
keyspace, not a universal constant; measured live rather than assumed).
Nothing has moved yet. This is a dry run.

Cleanup

T2–T5, T7
Ctrl+C

T1

Troubleshooting Common issues and their fixes

Windows 11: "An Application Control policy has blocked this file"

This is Smart App Control (Windows 11), not a bug in the demo. It blocks freshly-compiled, unsigned binaries that have no reputation yet, and a locally-built teaching sample will never have one. Confirmed by checking HKLM:\SYSTEM\CurrentControlSet\Control\CI\Policy → VerifiedAndReputablePolicyState.

Fix: Windows Security → App & browser control → Smart App Control → turn it Off. One real caveat, from Microsoft's own design: once off, it can only be re-enabled by resetting or reinstalling Windows. There is no per-app exception.

T1
rm -rf samples/sharded-orders-demo/bin samples/sharded-orders-demo/obj dotnet run --project samples/sharded-orders-demo -c Release -- topology

After turning Smart App Control off, delete the stale build output and rerun any command to confirm it works.

"Database error" / "Is docker compose up?"

The shard containers aren't running or aren't healthy yet. Run docker ps and confirm tadka-shard1-db through tadka-shard4-db (and tadka-shard5-db if you're past Step 4) all say healthy. If not, re-run Step 0's docker compose up -d and wait ~10 seconds.

A watch terminal shows "no schema yet"

You opened a watcher before running init (Step 0), or you're watching a shard id that hasn't been through add-shard yet. Run init (or add-shard --id N for a shard beyond the first four) and the watcher will pick it up on its next poll.

Topology shows fewer than 20,000 total rows after seeding

Seeding is deterministic and idempotent. If you ran seed more than once without a reset in between, later runs just insert 0 new rows (you'll see "N already present" in the output); they don't top anything up. If the total looks wrong, run reset and reseed fresh.
